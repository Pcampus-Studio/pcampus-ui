## Intent

**Why:** `dist/theme.css` was produced by `tailwindcss -i src/styles/theme.css -o dist/theme.css --minify` which compiled it into a full Tailwind output (`/*! tailwindcss v4.3.2 */`). This broke consuming services because:
- `@theme inline` in a compiled file is consumed, not re-exported
- Token names like `--pcampus-color-surface-card` existed in the source but were compiled away
- Every consumer had to manually duplicate the `@theme inline` bridge in their own globals.css

**Done when:**
- `dist/theme.css` is raw CSS: `:root { --pcampus-* }` + `@theme inline { ... }` (no Tailwind preamble)
- Consuming services only need `@source` + `@import "dist/theme.css"` — no manual bridge
- `--pcampus-color-surface-card` and `--pcampus-color-warning` tokens exist and resolve correctly

## Architecture

`dist/theme.css` correct usage (consuming service):
```css
@import "tailwindcss";
@source "../node_modules/@pcampus-studio/ui/dist/esm";   /* generates bg-pcampus-* classes */
@import "@pcampus-studio/ui/dist/theme.css";             /* tokens + @theme inline bridge */
@import "@pcampus-studio/ui/dist/motion.css";
```

`@source` is still required because `bg-pcampus-canvas`, `duration-panel`, `ease-default` etc. are used inside pcampus-ui components and must be in the consumer's Tailwind scan.
