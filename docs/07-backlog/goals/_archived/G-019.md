## Context

Consuming services (Notify Logs) need a day calendar. Native `datetime-local` is hard to use. This primitive belongs in `@pcampus-studio/ui`, not in each app.

## Intent

**Why:** Without a shared date picker, apps invent calendars or rely on native pickers that break in dark theme and iframes.

**Done when:** `DatePicker` / `DateRangePicker` are exported, locale-aware via `Intl`, values are `YYYY-MM-DD`, time stays on existing `Input type="time"`.

**Unblocks:** Notify Logs and other filter bars after publish.

## In

- `DatePicker` (single) and `DateRangePicker`
- `locale` via `Intl` (month names, weekdays, first weekday)
- `minDate` / `maxDate` / `maxSpanDays`
- Day cells use `--pcampus-radius-xl`
- Popover overlay from existing primitive

## Out

- Time-of-day UI (use existing `Input`)
- Timezone conversion (`Asia/Bangkok` stays in the app)
- Buddhist/Hijri calendars
- lucide / extra date libraries (Luxon, date-fns)

## Acceptance criteria

- [x] Selecting a day returns `YYYY-MM-DD`
- [x] Range is two clicks (start then end)
- [x] `th-TH` / `en-GB` change labels via `Intl`
- [x] No new date/time npm dependency
