## Context

G-001–G-007 implemented all components using inline React `style={}` objects. Inline styles cannot express pseudo-class states (`:hover`, `:focus`, `:active`, `disabled:`). The result: buttons don't change on hover, inputs have no focus ring — looks nothing like PBCP Cockpit.

Cockpit source of truth: `PBCP-Cockpit/code/app/globals.css` (Tailwind v4 `@theme inline`) and `PBCP-Cockpit/code/components/ui/button.tsx` (utility class strings).

## Intent

**Why:** pcampus-ui components must produce the same visual output as PBCP Cockpit. Any service consuming the library should look identical to Cockpit. Inline styles block hover/focus/active states entirely.

**Done when:**
- Storybook Button primary looks identical to Cockpit's button (same color, radius, hover, focus ring, disabled opacity)
- All G-003–G-006 components use `className` strings, no inline `style={}` for visual properties
- Pre-built `dist/index.css` ships with all utility classes; consumers need no Tailwind setup

**Unblocks:** Any service that imports `@pcampus-studio/ui` getting correct interactive states

## Architecture decisions

### Why Tailwind v4 (not CSS Modules or plain CSS)

Cockpit already uses Tailwind v4 as the canonical source of truth. Mirroring the same pattern in the library makes:
- Token-to-utility mapping maintainable (single `@theme inline` block)
- Component classes human-readable (`hover:bg-pcampus-primary-hover` vs complex CSS)
- Cursor agents produce consistent output across Cockpit and library

### Token name mapping

pcampus-ui uses the `--pcampus-*` prefix. The `@theme inline` block in `components.css` maps these to Tailwind utilities with `pcampus-` prefix on the utility name — **no conflict with Cockpit's own Tailwind setup** because class names differ:

| Utility class | CSS property | pcampus token |
|--------------|--------------|---------------|
| `bg-pcampus-primary` | `background-color` | `var(--pcampus-color-primary)` |
| `bg-pcampus-primary-hover` | `background-color` | `var(--pcampus-color-primary-hover)` |
| `text-pcampus-on-primary` | `color` | `var(--pcampus-color-text-inverse)` |

### Step 3 — Rewrite Button (reference implementation)

```tsx
import { clsx } from 'clsx';

const variantClass = {
  primary:     'bg-pcampus-primary text-pcampus-on-primary hover:bg-pcampus-primary-hover disabled:opacity-60',
  secondary:   'border border-pcampus-hairline-strong bg-pcampus-surface-card text-pcampus-ink hover:bg-pcampus-canvas-soft disabled:opacity-60',
  ghost:       'text-pcampus-body hover:bg-pcampus-canvas-soft disabled:opacity-60',
  destructive: 'bg-pcampus-error text-pcampus-on-primary hover:opacity-90 disabled:opacity-60',
} as const;

const sizeClass = {
  sm: 'h-8 px-[10px] text-xs gap-1',
  md: 'h-10 px-[18px] text-sm gap-2',
  lg: 'h-12 px-5 text-[15px] gap-2',
} as const;

// In JSX:
<button
  className={clsx(
    'inline-flex items-center justify-center rounded-pcampus-md font-pcampus-sans font-medium',
    'cursor-pointer transition-all outline-none whitespace-nowrap',
    'focus-visible:ring-2 focus-visible:ring-pcampus-primary focus-visible:ring-offset-1',
    variantClass[variant],
    sizeClass[size],
    isDisabled && 'cursor-not-allowed',
    className,
  )}
  ...
/>
```

Apply same pattern to all components in steps 3–6.

### Step 4–6 — Rewrite remaining components

Use the same `clsx()` + named variant/size constant pattern as Button. Remove all `style={}` props that set visual properties. Allow `className` prop passthrough on every component.

Key classes for common patterns:

**Form input base:** `h-10 w-full rounded-pcampus-md border border-pcampus-hairline bg-pcampus-canvas px-3 text-sm text-pcampus-ink placeholder:text-pcampus-muted focus:outline-none focus:ring-2 focus:ring-pcampus-primary focus:border-transparent disabled:opacity-50`

**Modal overlay:** `fixed inset-0 z-30 bg-black/40 backdrop-blur-sm`

**Modal panel:** `relative bg-pcampus-canvas rounded-pcampus-lg shadow-lg`

**Toast base:** `flex items-start gap-3 rounded-pcampus-md border border-pcampus-hairline bg-pcampus-surface-card p-4 shadow-md`

## Notes for AI

- **Read first:** `PBCP-Cockpit/code/components/ui/button.tsx` — exact class pattern to mirror
- **Read first:** `PBCP-Cockpit/code/app/globals.css` — `@theme inline` reference; use same approach, different token prefix (`pcampus-`)
- **Key invariant:** Never remove the `--pcampus-*` CSS custom properties. The `@theme inline` block creates Tailwind utilities _from_ those vars — both must exist
- **`className` passthrough:** all components must accept and forward `className` prop — consumers need to be able to add spacing (`mt-4`, `w-full`) without overriding internals
- **No Tailwind in peer deps** — Tailwind is a devDependency that compiles to plain CSS output; consumers don't install it
- **Storybook import path:** change from `../src/tokens/index.css` to `../src/styles/components.css`
- **`clsx`** is preferred over template literals — handles conditional classes cleanly
- **Do NOT** use `@apply` inside component files — only in `components.css` if needed for global base styles
