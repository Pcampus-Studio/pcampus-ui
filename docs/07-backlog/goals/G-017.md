## Context

The Mail Templates block editor (G-032) needed a "collapse all but one" pattern; it was built app-local. Extracting a generic `Accordion` into `@pcampus-studio/ui` lets Mail, Storage, and Content-OS reuse one consistent, token-driven collapsible instead of re-implementing it.

## Intent

**Why:** Avoid each app re-inventing accordion behaviour + styling; keep the design system the single source of the look.

**Done when:** `Accordion` is exported from `@pcampus-studio/ui`, token-driven, theme-aware, with flexible slots (leading badge/handle, trailing actions that don't toggle, subtitle), single or multiple open modes, controlled or uncontrolled.

**Unblocks:** migrate Mail `block-builder` onto `Accordion`; Storage file groups; any collapsible list.

## In

- `Accordion` + `AccordionItem`/`AccordionProps` types in `src/patterns/accordion.tsx`
- Single (default, one open) and multiple modes; controlled `openIds` or uncontrolled `defaultOpenIds`
- Slots: title, subtitle, leading, actions (stopPropagation), body; chevron rotates; token-driven

## Out

- Drag-to-reorder (consumers add their own handle in `leading`/`actions`)
- App-specific block editors (stay in their apps)

## Acceptance criteria

- [x] `Accordion` exported from `@pcampus-studio/ui` (patterns)
- [x] Single & multiple modes; controlled + uncontrolled open state
- [x] Actions slot clicks do not toggle the row
- [x] Token-driven (no hardcoded hex); theme-aware (light/dark)
- [x] `tsc --noEmit` passes (no new `src/` errors)
